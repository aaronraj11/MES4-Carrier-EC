# MES4-Carrier-EC: handoff for the next Claude session

Written 2026-10-27 at the end of the first design session. Read this file first, then `README.md`.

## How this schematic is made

The schematic is **generated by Python**. Change the generator, not the `.kicad_sch` files: hand edits are overwritten on the next run.

| Path | What |
|---|---|
| `generator/run.sh` | Regenerates everything, then runs ERC, exports the netlist and writes `MES4_Carrier_EC.pdf`. **Close KiCad first**: on exit KiCad rewrites `MES4_Carrier_EC.kicad_pro` from its stale copy, which drops the net classes. Re-run `run.sh` if that happens. |
| `generator/gen.py` | One function per sheet: `main_sheet`, `can_sheet`, `power_sheet`, `relay_sheet` (×2), `sensor_sheet`, `loadcell_sheet`, `aux_sheet`, `winch_sheet`, `add_expander`, `root_items`. Note texts use `{tag}` / `{Sheet/tag}` placeholders that resolve to reference designators. |
| `generator/parts.py` | `NEWP`: every part that isn't copied from the MES4-Flasher, with a **verified** LCSC number. |
| `generator/builder.py` | Sheet builder. `fix_junctions`, `prune` / `clean`, `assign_refs` (annotation), multi-unit support, and `from_template`, which re-UUIDs everything it copies. |
| `generator/can_parts.py`, `aux_parts.py` | Project symbols and footprints: 1×4 RJ45, URB 10 W / 20 W, TCA9535, IM03GR, KF250NH-4P. They're copied from the MES3.1 / MES2 Harvester / MES2_Extension projects and upgraded with `kicad-cli fp upgrade`. |
| `generator/libs.py` | Rebuilds `MES4-Carrier-EC.kicad_sym`, `.pretty/` and `.3dshapes/` from what the sheets use. |
| `generator/netdump.py` | `python3 generator/netdump.py <netlist> /SheetName/` prints every part's pin → net. |

Several sheets are **templates from `../../MES4-Flasher/`**: Relays, Sensors, LoadCell and Main. That's done with `Sheet.from_template`, followed by deleting regions, relabelling and swapping parts.

Checks to run after every change (they all passed at handoff):
- ERC: 0 errors, 0 warnings.
- Every symbol pin has a footprint pad.
- No single-pin nets.
- No duplicate UUIDs.
- Every purchased BOM line has an LCSC number (the net tie and bare test pads have none).

The checks are inline Python in this session's history. Re-create them from `netdump.py` plus the `kicad-cli sch export bom` output, or add them to `run.sh`.

**Rules the user set:**
- Every part needs a real, checked LCSC number. Never guess one; check `https://wmsc.lcsc.com/ftps/wm/product/detail?productCode=Cxxxx`.
- LEDs must be JLC **Basic** parts.
- Write in the Flasher's style.

### 2. Move the winch onto the TCA9535 and photoMOS SSRs (user's choice)

PA0 / PA1 must go back to coil feedback, so the winch comes off them. The user chose a **solid-state "one relay" style** design:
- **Expander:** move the TCA9535 (U4, `add_expander`) to the Winch sheet. Use P00 = winch A and P01 = winch B as **outputs**. Its INT stays not connected, since no pin is free.
- **SSRs:** two **Cosmo KAQY214S** (LCSC **C2890344**, 4,180 in stock): 400 V, 130 mA, 20 Ω, SOP-4 2.54 mm. Pins: **1 LED anode, 2 LED cathode, 3 / 4 output (AC/DC)**. Ratings: IFON ≤ 3 mA, VF 1.2 V, VR 5 V.
  - No dual-channel photoMOS was in stock: AQW214SZ C2152188 had 0, KAQW214S C194896 had 0, and KAQW214 DIP C194714 had 15.
- **Interlock: LEDs back-to-back.**
  - Wiring: P00 → one series resistor → node A. Node A goes to SSR1 pin 1 and SSR2 pin 2; SSR1 pin 2 and SSR2 pin 1 go to P01.
  - P00 high and P01 low turns on SSR1 (CLK); the reverse turns on SSR2 (ACLK). Equal levels, or inputs at power-up, turn both off. The off LED only ever sees about 1.2 V reverse.
  - Size the resistor for IF ≈ 5 mA: (3.3 − 1.2 − ~0.3) / 5 mA ≈ 330 Ω. **Check the LCSC number for 330 Ω 0402** before using it.
- **Outputs:** SSR1 3 / 4 between WINCH_COM and WINCH_CLK, SSR2 between WINCH_COM and WINCH_ACLK, into the existing J18 (1 CLK, 2 COM, 3 ACLK).
- **Remove** K5 / K6 (IM03GR), Q6 / Q7 and their parts from `winch_sheet()`. Keep the IM03GR library code in case the user wants the relay version back.
- **Symbol / footprint:** KiCad `Relay_SolidState:CPC1017N` has the same pin numbering. **Check the footprint** (`Package_SO:SOP-4_3.8x4.1mm_P2.54mm` or `SO-4_4.4x…_P2.54mm`) against the Cosmo pad layout: the datasheet is LCSC C2890344's PDF, "Recommended Pad Layout" near the end. You can also pull the EasyEDA pads with `https://easyeda.com/api/products/C2890344/components?version=6.4.19.5` (ask WebFetch to copy the `PAD~` strings verbatim).
- **Safety:** the TCA9535 **keeps its outputs through an MCU reset**, so firmware must turn the winch off as its first I²C write at start-up. If that's not acceptable, the TCA9539 (same family, RESET pin; tie it to module NRST) is the alternative. Verify its LCSC number first. Tell the user about this trade-off.
